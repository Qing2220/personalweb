# 附录 · 课件与线上训练站的差异清单

> 比对对象：
> ① 课件 `FDE九阶段流程课件.html`（2026-11 版，27 项任务）
> ② 线上站 `https://fde-discovery-lab-67046.app.workbuddy.host`
> 比对时间：2026-11-19｜比对方式：课件逐条 vs 站点接口数据（`/api/projects/catalog`、`/api/training/state?caseKey=*`）与前端脚本（`training.js`、`fde-flow.js`）
> **本文只记录差异，不含改动方案。** 结论按"会不会让学员走错"分级。

---

## 一、先确认对得上的部分（避免只报问题）

| 项 | 课件 | 站点实际 | 结论 |
|---|---|---|---|
| 阶段数 / 任务数 | 9 阶段 × 3 任务 = 27 | `curriculum.stages` 长度 9，每阶段 `steps` 长度 3 | 一致 |
| 阶段名与顺序 | 业务挖掘 → 现场调研 → 需求定义 → 方案设计 → 构建集成 → 测试评估 → 客户试点 → 上线交接 → 运营迭代 | 同 | 一致 |
| 阶段关卡文案 | 如"业务负责人确认问题、指标口径与调查范围" | `stages[0].gate` 逐字相同 | 一致 |
| 案例数 | 5 个综合案例 | `calder/helix/huaheng/qinghe/harmony` | 一致 |
| 六角色构成 | 每个案例固定 6 人 | `caseInfo.roles` 均为 6 人，姓名与岗位逐字对应 | 一致 |
| 访谈线索总量 | 6 人 × 6 条 = 36 | `discovery.total = 36` | 一致 |
| 任务入口映射 | 01-1 简报、01-2 证据与验收台账、01-3 角色访谈、02-2 三视角工作台、04-3 ROI、05 原型与评估… | `fde-flow.js` 的 `toolLabel` 一一对应（brief / workflow / interview / whiteboard / roi / prototype / assessment / engagement / client） | 一致 |
| 实验室路由 | `/case-lab?case=案例key`、`/group-training` | 5 个案例 + 集团项目均返回 200 | 可用 |

> 说明：这一层做得比课件描述的还细——站点把"访谈任务"直接映射到了对应工具，而不是让学员自己找入口。

## 二、差异清单

### S1 ｜高｜7 项"必做访谈"在站点上没有标记，其中 5 项没有访谈入口

- **课件**：明确 7 项必做访谈 —— 01-2 核基线、01-3 问决策链、02-1 六角色、07-2 用户验收、08-1 三方评审、08-3 交接签收、09-2 事件演练。
- **站点**：27 个任务只有 `tool` 字段，没有 `interview: required/optional` 这类标记；任务卡上也不显示"必做访谈"徽标。
- **具体缺口**：只有 2 个任务走 `interview` 工具（01-3、02-1）。另外 5 项分别被映射为——
  - 01-2 → `workflow`（证据与验收台账）
  - 07-2 → `engagement`（客户会议与验收）
  - 08-1 → `workflow`（台账）
  - 08-3 → `engagement`（会议）
  - 09-2 → `client`（客户现场事件）
- **影响**：学员按站点界面推进，会把"08-1 三方评审"当成填一张表，而不是"业务 / 技术 / 风险三方各表态"。这恰好是课件反复强调不能犯的错。
- **证据**：`/api/training/state?caseKey=calder` 中 9×3 个 step 的 `tool` 取值；`fde-flow.js` 第 22 行 `toolLabel` 映射表。

### S2 ｜高｜点击访谈类任务后页面无反应（容器缺失）

- **现象**：训练页处理访谈任务时执行 `section='flow'` 后调用 `$('lab-workspace')?.scrollIntoView(...)`。
- **问题**：`lab-workspace` 这个 id 在训练页打包产物中**只被查询 3 次，从未被创建**（`training.js` 出现 3 次，全部是 `$('lab-workspace')`；`fde-flow.js` 中 0 次）。可选链 `?.` 会让它静默失败。
- **影响**：点击"进入角色访谈"后既不跳转也不报错，学员会认为按钮坏了。
- **证据**：`grep -c "lab-workspace" training.js` → 3（均为查询）；`fde-flow.js` → 0。

### S3 ｜中｜阶段关卡表单未渲染，关卡无法在页面执行

- **课件**：关卡要填"状态、评审人、依据、结论"，且"三项任务全完成 + 前序关卡通过"才能选"通过"。
- **站点**：`fde-flow.js` 里有 `collectFlowGate()`，靠 `[data-flow-gate]` 和 `[data-gate-field]` 采集；但这两个属性全站只在采集函数里出现过一次，**没有任何模板渲染它们**。实际渲染的关卡区块只有三个按钮（导出报告、直接导出、进入下一环节）。
- **影响**：`collectFlowGate()` 恒返回 `null`；课件的"关卡放行"在站点上退化为"点按钮进入下一环节"，没有评审人、没有依据、没有前置校验。
- **证据**：`grep -c "data-flow-gate"`：`fde-flow.js` = 1（第 24 行采集器）、`training.js` = 0。

### S4 ｜中｜课件说"03 之后不要再找实验室"，站点却全程可达

- **课件**：虚拟实验室只在阶段 01、02 开放，"03 之后不要再去实验室找入口，那里没有"。
- **站点**：`/case-lab?case=*` 是独立页面，任何时刻直接访问都是 200；训练页也有 `action==='case-lab'` 的处理分支，不区分当前阶段。
- **影响**：学员在阶段 05 仍可回到 3D 现场"再聊一轮"，与"阶段 03 起只引用已采集证据编号"的原则冲突。
- **说明**：这不是 bug，是产品取舍。但课件把它写成了硬规则，两者必须有一边让步。

### S5 ｜低｜案例名称不一致

- **课件**：`鸿蒙设备告警`
- **站点**：`鸿蒙设备协同`（`caseInfo.company`、案例卡片）
- **影响**：学员按课件名字在站内搜不到；口头答辩时名称对不上。
- **证据**：`/api/training/state?caseKey=harmony` → `caseInfo.company = 鸿蒙设备协同`。

### S6 ｜低（课件自身问题）｜华衡智造"02-1 找谁"与六角色表对不上

- **六角色表**：周明远、陈思雨、王建国、沈悦、许文静、李佳宁。
- **02-1 的"找谁"**：陈思雨、李佳宁、王建国、**孙立新（仓储）**、许文静、沈悦 —— 用孙立新替换了周明远。
- **核对结果**：孙立新确实存在于站点的"利益相关者地图"（共 11 人，含孙立新/唐晓峰/何文博/刘志强等），但**不属于 6 个核心访谈角色**。
- **影响**：学员按 02-1 的名单谈完 6 人，会漏掉 Buyer（周明远），拿到的是"运营层 + 中层"的视角，缺决策权信息。
- **建议口径**：核心 6 人固定，其余 5 人作为"按需补访"，在文档里分开写。

### S7 ｜提示｜"阶段工作台在页面顶部"与站点结构不符

- **课件**："切到阶段 01/02，页面顶部就是阶段工作台，点『进入 3D 业务现场』"。
- **站点**：阶段页是"9 阶段导航 + 当前阶段 3 张任务卡 + 关卡区块"，实验室是独立的 `/case-lab` 页面，不在阶段页顶部。
- **影响**：按课件找"页面顶部的实验室按钮"会找不到。

## 三、按影响排序的处理建议（不做取舍，只列优先级）

| 优先级 | 项 | 一句话 |
|---|---|---|
| P0 | S2 | 按钮点了没反应，属于"功能看起来坏了"，先修 |
| P0 | S1 | 学员漏掉 5 项必做访谈，直接导致交付物缺证据 |
| P1 | S3 | 关卡没有评审留痕，等于没有关卡 |
| P1 | S6 | 课件名单与角色表打架，学员照做会漏 Buyer |
| P2 | S4 / S5 / S7 | 文档与命名对齐即可，不改架构 |

## 四、比对方法与可复现命令

```bash
# 1. 站点目录（9 阶段、案例、模块）
curl -s "$HOST/api/projects/catalog" | python -m json.tool | head -40

# 2. 单案例 27 项任务与工具映射（把 calder 换成 helix/huaheng/qinghe/harmony）
curl -s "$HOST/api/training/state?caseKey=calder" \
  | python -c "import json,sys; d=json.load(sys.stdin); [print(s['title'], [t['tool'] for t in s['steps']]) for s in d['curriculum']['stages']]"

# 3. 六个核心角色与被访谈线索数
curl -s "$HOST/api/training/state?caseKey=huaheng" \
  | python -c "import json,sys; d=json.load(sys.stdin); print([r['name'] for r in d['curriculum']['caseInfo']['roles']]); print(d['curriculum']['discovery']['total'])"

# 4. 关键路由可用性
for u in "/case-lab?case=calder" "/group-training" "/laboratory"; do curl -s -o /dev/null -w "$u %{http_code}\n" "$HOST$u"; done

# 5. 验证 S2/S3（容器与关卡表单是否存在）
curl -s "$HOST/training.js" -o t.js; grep -c "lab-workspace" t.js
curl -s "$HOST/fde-flow.js" -o f.js; grep -c "data-flow-gate" f.js
```

> 第 5 组命令是判定 S2、S3 的唯一依据：查询次数 > 0、渲染次数 = 0，就证明容器/表单缺失。
