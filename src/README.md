# src · 代码占位

本目录按 FDE 九阶段节奏使用：**阶段 05（构建集成）之前不放业务代码**。

## 为什么现在空着

阶段 01–03 的产出是"证据与判断"，不是程序。此时写代码会有两个后果：

1. 需求还没定稿，代码会把错误的假设固化下来；
2. 阶段 04 的权限矩阵、人工复核点还没评审，代码里的校验位置一定是错的。

## 阶段 05 开工时的目录约定（先定规则，再写代码）

```text
src/
├─ config.yaml            配置：模型地址、阈值、开关（禁止硬编码）
├─ app/
│  ├─ main.py             入口：启动校验 + 路由注册
│  ├─ config.py           config.yaml 读取与必填校验（缺失即启动失败）
│  ├─ common/
│  │  ├─ response.py      统一返回 {ok, data, error{code,msg}}
│  │  └─ errors.py        错误码表
│  ├─ guards/
│  │  ├─ auth.py          身份与角色
│  │  ├─ permission.py    权限校验（谁读什么、写什么）
│  │  └─ redline.py       数据红线：患者标识字段出站拦截
│  ├─ domain/
│  │  ├─ slot.py          号源一致性校验（只读）
│  │  ├─ triage.py        分诊信息补全（不给定科结论）
│  │  └─ handover.py      人工确认与转派
│  └─ audit/
│     └─ trace.py         每次输出记录：来源、规则、模型版本、确认人
└─ tests/
   ├─ test_redline.py     红线：患者标识不得进模型上下文
   ├─ test_permission.py  越权必须拒，且返回统一错误结构
   └─ test_triage.py      分诊只给建议，不给结论
```

## 三条必须落在代码里的硬约束（来自阶段 01–03 的证据）

| 约束 | 依据 | 落点 |
|---|---|---|
| 患者姓名/身份证/病历号/手机号不得进入模型上下文与日志 | `EV-125`、`EV-126` | `guards/redline.py`，出站前统一拦截 |
| 分诊只给"信息补全与科室建议"，不得直接定科 | `EV-126`（分诊属医疗行为） | `domain/triage.py`，输出必须带 `suggestion_only=true` |
| 任何对外发送、加号、补录必须留操作人与工号 | `EV-128`、`EV-130`、`EV-106` | `audit/trace.py`，无工号直接拒 |

> 这三条不是"最佳实践"，是访谈里被人明确说过的红线。写代码时可以争论实现，不能争论要不要。
